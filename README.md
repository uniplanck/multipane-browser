# MultiPane Browser

1つのウィンドウに最大10ペインを並べられる、Chromium（Electron）ベースのmacOS向けブラウザです。複数の Grok Bot チャット（grok.com/bot/…）を横並びで監視する用途向けに作っています。

> 非公式ツールです。xAI / X Corp. とは一切関係ありません。

## 主な機能
- **レイアウト**: 2x1 / 3x1 / 4x1 / 2x2 / 3x2 / 4x2 / 3x3 / 5x2。ペインを閉じると残りを自動で均等配置（auto-fit）
- **スプリッター**: ペイン間をドラッグで幅・高さ調整（レイアウトごとに保存、ダブルクリックで均等に戻す）
- **ドッキング型の並べ替え**: ペインのヘッダーをつかんで別のペインの上へ運ぶと、上/下/左/右のどこに入るかを薄い赤のプレビュー（置いた後にそのペインが占める範囲）で表示し、離すとそこへ移動。上/下はそのペインだけを縦に分けて重ねる（同じ段の他のペインの高さは変わらない。1セル最大3枚、段が1〜2のときだけ、各段で最も多く重ねたセルの枚数の合計が3以下に収まるときだけ）、左/右は隣との間に新しい列として入る（重ねたセルならその左/右）。段の上端・下端の帯へ運ぶと横幅いっぱいの新しい段になる（段が3つのときは無反応）。段が3つになる（または縦の合計が3を超える）と重ねは自動で解除し、下側のペインを決まった規則でペインの少ない段へ移す。抜けた跡は閉じたときと同じ規則で詰める。自分自身の上・配置が変わらない位置・上限を超える位置ではプレビューを出さず何もしない。Esc・他のアプリへの切替で取消。ドラッグ中はペインの表示を静止画に置き換える（ページそのものは止めない）。上部のタブのドラッグは従来どおり入れ替え。重ねた配置は `panes.json` の `stacks`（任意項目。`rows` は重ねた分も数えるので古いバージョンは横並びで読む）とワークスペースに保存
- **未読カウント / 光る枠**: 自分の最後の送信以降に届いたBotの返信数をタブとペインに表示、更新があったペインはオレンジに光る
- **マーカー表示（最新のBotメッセージの末尾で判定。罫線・スペース・全角スペース・`◆ 日時 ◆` の違いは吸収）**
  - 🟢 **待機中**（緑・通知/Dockバッジ対象）: `🟢 ━━ 《 待機中 》 ━━ 🟢`（`待機中30` / `待機中60` も可。旧表記 `入力待機中` / `入力待ち` / `出力待ち` と `◆ ━━ … ━━ ◆` も引き続き待機中として扱う）
  - 🟣 **終了**（紫・光らない／通知・Dockバッジなし。数字は紫で表示）: `🟣 ━━ ［ 終　了 ］ ━━ 🟣`（「終」「了」の間は全角スペース。半角/なしも可）
  - 🔴 **作業中**（赤）: `🔴 ━━ 【 作業中 】 ━━ 🔴`
  - 複数あれば末尾に近いものが優先。自動スリープ（作業中・マーカーなし・フォーカス中・最大化中は対象外）: 🟣終了は終了を検知して**1分後**、🟢待機中は**30分後**。入力欄に文字・下書き・添付があるペインは眠らない（スリープ直前にも再確認）。待機中でスリープしたペインには、マーカー直上の引用（依頼内容）をスリープ画面に表示。スリープ画面の最上部にはボット名（大）とグループチャットならグループ名（小）も表示（ページの見出しから取得、取れなければタブタイトル）。スリープ中も色（紫/緑）を保ち、新着確認（水色＝未開封）の対象。新着確認は通常5分ごとに1枚ずつで、失敗が続くペインは最長60分まで間隔を空ける。スリープ画面に「最終確認 hh:mm・次回 hh:mm」/「確認失敗（n回）・次回 hh:mm」を表示し、ログイン画面を確認したときは全ペインの確認を止めて「ログインを確認」「確認を再開」を出す。再読み込み・移動・返信の生成中などで今の状態をまだ確認できていない間は、表示中の色は「最終確認」（薄く表示）で、自動スリープしない
- **クラウドPC自動最大化**: ページの「コンピュータを表示」を開くと、そのペインを自動で最大化してサイズ上限を解除（閉じる / Esc で元に戻る。すでに最大化中ならそのまま大きく表示し、閉じても縮めない）。表示メニューでON/OFF（既定ON）
- **閉じたペインを開き直す**（⌘⇧T / 上部の ↩ ボタン / ファイルメニュー / コマンドパレット）: ウィンドウごとに直近10個まで、新しく閉じたものから順に。閉じた行・位置・URL・名前・色・ズーム・自動リロード・ミュート・スリープ設定を復元（新しいペインとして読み込み直す）。**下書き・添付・入力中の内容は戻らない**（入力のあるペインを閉じるときの確認にもそう表示）。履歴は起動中のメモリだけで `panes.json` には書かず、終了・再起動で消える。1枚ずつ閉じたペインだけが対象で、まとめて閉じたもの（レイアウト変更・ワークスペース切替・他のペインをすべて閉じる）と新しいタブ（空のペイン）は載らない。ペインが10枚あるときは何もせず、履歴も減らない
- **対応キュー**（上部の「対応 n」/ コマンドパレット）: ウィンドウのペインのうち次に確認するものを 要返信 → 未確認の新着（スリープ中の新着）→ 観測異常（ページ停止・読込失敗・応答なし・ログイン画面・新着確認の停止/失敗・🟢が最終確認値だけで今の状態は未確認）→ 待機中 の順に1ペイン1行で一覧（同じ種類は該当した順）。名前・理由・最終確認を表示し、文字で絞り込める。開く・絞り込み・ホバー・↑↓では既読・通知・Dockバッジ・フォーカスは変わらず、↵ / クリックで選んだときだけそのペインへ移動（スリープ中は読み込み待ちの順番で起こす。既読になるのは実際に表示されたときだけ）。選ぶまでに閉じた・別の会話に移ったペインには何もせず理由を表示。esc で閉じて元のペインに戻る。「未返信 n」と ⌘J（次の未読へ）は従来どおり
- **キーボードでのペイン移動**（ペインメニューにも）: ⌘⌥←/→ で同じ行の左右（行をまたがない）、⌘⌥↑/↓ で上下の行のうち中心が最も近いペイン（同じ距離なら左）。縦に重ねたセルでは ⌘⌥↑/↓ はまずセルの中を上下し、端から隣の行へ（⌘⌥←/→ はセル単位、重ねたセルへは高さの近いペインへ）。端では何もしない（反対側へ回り込まない）。⌘⇧J で対応キューの次の項目へ（今のペインが一覧にあればその次、なければ先頭。末尾の次は先頭。今のペインだけなら何もしない）。移動はクリックと同じ（最大化中は移動先が最大化、スリープ中は読み込み待ちの順番で起こし、表示されてからキーボードを渡す。その前に移った・入力した場合は渡さない）。既読になるのは ⌘⇧J で実際に表示されたときだけ。変換中（IME）・パレットや入力欄のあるダイアログを開いている間・キーを押し続けたときは移動しない。修飾キーなしの矢印・Enter・Esc やページの編集キー（⌘A ⌘C ⌘V ⌘Z など）は使わない
- **通知 & Dockバッジ**: 新着返信でmacOS通知（クリックでそのペインへ。既読にはしない）、Dockに未読合計。同じ待機は1回だけ通知し、4秒以内に複数ペインなら「Bots：確認待ち n件」の1通にまとめる（ペイン名・本文は出さない。クリックはアプリを前面に出すだけ）。設定 >「静音時間」（オフ / 22:00〜07:00 / 23:00〜08:00 / 00:00〜06:00）の間と通知オフ・ペインのミュート中に来た分は捨て、明けてもまとめて出さない（光る枠・未読・Dockバッジは通常どおり）
- **お気に入りバー**: クリック=選択中のペイン / ⌘クリック=新しいペイン / ⇧クリック=別ウィンドウ / 右クリック=メニュー
- **タブ**: 均等幅・名前編集・右クリックメニュー（閉じる / ペインごと閉じる / 複製 / 他を閉じる など）、コンパクトモード（⌘⇧C）
- **保存レイアウト（ワークスペース）**: ペイン構成を名前付きで保存・ワンクリック切替
- **一斉送信**（⌘⇧B / コマンドパレット）: 本文と送信先（Grokのペイン）を選んで「プレビュー」→ 送信先ごとの状態（送信可・起床待ち・スキップと理由）と件数を確認 →「このN件に送信」。下書き・添付・アップロード中・変換中・入力欄を確認できない・読み込み中・Botの会話を確認できない（返信の生成中を含む）ペインには送らず、入力欄の内容も変えない。スリープ中のペインは起こしてから同じ確認をする。送信先ごとに 未送信 / 準備中 / 送信開始 / 確認済み / 結果不明 / スキップ を表示し、「結果不明。チャットを確認してください」は自動で再送しない。取消は未送信分だけ
- **使用量表示**: サブスクの使用量を「残 / 使」切替で表示（grok.comのログインセッションから読み取り専用で取得）
- **grokfix**: grok.com/bot の直リンクがサイドバーしか描画されない問題を、サイト内遷移で回避
- 単一ペイン最大化（⌘\（JISは⌘¥も）・ヘッダーのダブルクリック）
- 使用量ポップオーバー: ホバーで期限・残り・「今日使える目安」を表示（目安 = (残り% − 余裕) ÷ 日数、毎日9:00に日付切替）
- 一括更新（⌘⇧R）
- **障害を区別した限定復旧**: 読み込みが遅いだけ（SLOW）・応答なし（HANG。遅いだけかもしれないので再読み込みしない）・読み込み失敗・ページの終了（renderer gone）を区別する。一時的な読み込み失敗（接続・DNS・タイムアウトなど）だけを自動で再読み込みし（1回目は約15秒後、2回目は約60秒後）、**1ペインにつき10分に2回まで**。永続的な失敗（証明書・ブロックなど）や ERR_ABORTED（意図したキャンセル）、サブフレームの失敗は再試行しない。ページが終了（クラッシュ等）したペインは自動では直さず、「停止」のプレースホルダーを出して手動の再読み込みを待つ（再読み込みで解除。入力中の下書きが戻らないことがある）。自動の再読み込みは入力保護（#11）とロードキュー（#31）を通る
- 下端の余白: 最下段のペインの下の余白を 6px から 5px に変更（`BOTTOM_GAP`。ペイン間の隙間は変更なし）
- コマンドパレット（⌘K）

- **構成の保存**: ペイン構成（行・列・URL・名前など）は変更の0.2秒後と終了時に `panes.json` へ保存。起動のたびに直近5世代を `panes.json.日時.bak` として同じフォルダに残す（誤って上書きしても戻せる）
  - 保存は同じフォルダの一時ファイルに書いて fsync してから置き換えるので、途中で落ちても前回の `panes.json` が残る。置き換える前の正常な内容は `panes.json.prev-1〜3` として3世代残す。保存要求には番号を振り、古い内容が新しい内容を上書きしない。終了時の保存待ちは最大3秒
  - 読めない（壊れている・形式が違う）か新しいバージョンで保存された `panes.json` は、読み込みも上書きもしない（自動保存を停止）。起動時に復旧画面が開き、読める保存世代（prev / .bak）から復元するか、新しい構成で始めるかを確認付きで選べる。元のファイルは `panes.json.broken-日時`（新しいバージョンのものは `.newer-日時`）として残す
  - 保存に失敗したときは表示はそのままで、上部に「⚠ 保存できません」が出る（クリックで再試行）。突然の電源断で直前の変更がすべて残ることは保証しない
  - **前回のスリープ状態を復元**（設定 >「前回のスリープ状態を復元（再起動後）」・**既定OFF**）: ONのときだけ、保存時にスリープ中だったペインに最小限の記録（保存時刻・スリープ中だったこと・最後に確認したマーカー🟢🟣🔴とその確認時刻・スリープ画面のボット名/グループ名）を `panes.json` に足し、次の起動ではそのペインを**読み込まずにスリープ画面から開始**する（起動時の読み込みが集中しない。クリック・フォーカスで通常どおり復帰し、読み込みは順番待ちを通る）。スリープ画面には「前回 🟢 待機中・未再確認（hh:mm 時点）」のように前回の記録であることを表示し、色・未読・光る枠・Dockバッジ・通知・水色（未開封）は前回の記録からは出さない。裏の新着確認（5分後〜）が成功すると「再確認: …」に変わる（最初の確認は基準取りで通知しない）。7日より前の記録・時刻が合わない記録はマーカーを出さずに名前だけ表示する
  - 「スリープ中の引用も保存（最大300文字）」（既定OFF）をONにしたときだけ、🟢待機中のペインの引用も記録する。OFFにすると次の保存で消える。下書き・下書きの有無・添付・ページ全体・未読数・認証情報は常に保存しない
  - OFFのときは記録を書かず（次の保存で残っていた記録も消える）、記録があっても使わずに全ペインを従来どおり読み込む。`panes.json` の形式（schema 1）は変わらず、古いバージョンは追加項目を無視する。壊れた・新しい版の記録は無視してそのペインを通常どおり読み込む。読めない/新しいバージョンの `panes.json`（復旧画面）では何も復元しない
  - 開発時は `MPB_USER_DATA=/tmp/任意のフォルダ npm start` で、本番とは別のプロファイル（userData・sessionData）で起動できる

## 使い方
```sh
npm install
npm start                # 開発起動
npm run dist:mac         # .dmg / .zip をビルド
npm run install:mac      # arm64 の .app をビルドして /Applications にインストール（ad-hoc署名）
npm run build:preload    # src/pane-preload.js を生成（下記）
npm run check:preload    # 生成物が最新か確認（変更しない。古い/無いと exit 1）
```
- `src/pane-preload.js` は**生成物なので直接編集しない**。ペインの preload は sandbox で動きローカルファイルを `require` できないため、マーカー判定・引用抽出・下書き判定（`src/pane-rules.js`、main とテストも同じものを `require`）を `scripts/build-pane-preload.js` が `src/pane-preload.template.js` に組み込んで作る。どちらかを編集したら `npm run build:preload`。`npm start` とパッケージング（electron-builder の `beforePack`）の前に自動で確認し、古ければ止まる
- IPC: main が受け取る全チャンネルは `src/ipc-policy.js` の表にあり、受信は `src/main.js` の `ipcOn` / `ipcHandle` だけ。main が作った画面（ウィンドウUI・overlay・ペイン・裏の新着確認・承認Bot）を役割つきで登録し、登録済みの送信元・トップフレーム・同梱画面（file: は index.html / overlay.html と一致するときだけ）または許可origin・そのウィンドウにある対象・引数の型と範囲をすべて満たす送信だけを処理する。満たさない送信は何もせずに捨て、デバッグログには固定コード（`E_ROLE` など）だけを残す（内容・URLは出さない）。チャンネルや引数を変えたら `src/ipc-policy.js` も直し、`node test/ipc-policy.test.js` で確認する（実際の preload / renderer / overlay の送信が通ることも検査）
- 世代（`src/pane-state.js`）: main がペイン実体・ページの世代（読込・再読み込み・URL/SPA移動・スリープ・起床・レンダラ終了ごとに更新）・裏の新着確認の実行に起動ごとの通し番号を振り、ページの preload は受け取った番号と走査番号を件数の報告に付ける。main は報告を付いていた世代の中だけで比べ、閉じたペイン・古いページ/URL/新着確認・重複・逆順の報告は何も変えずに捨てる（診断は `count.drop` の固定コード）。番号は保存しない
- 入力の保護（`src/draft-guard.js`）: ページを捨てる操作の直前に、main が入力欄をその場で読む（`src/pane-rules.js` の `composerState`。本文は返さず、有無・添付・アップロード・短いハッシュだけ）。自動スリープ・自動リロード・真っ白なBotの再読込は、入力・添付・変換中（IME）・確認できない・一斉送信中なら行わない（次の機会に再確認）。閉じる（✕ / ⌘W / メニュー）・再読み込み（↻ / ⌘R）・一括更新・今すぐスリープ・URL変更（アドレスバー / パレット / お気に入り / 上限時の⌘T / ページ内のgrok.comリンク）・戻る/進む・レイアウト変更で閉じるペイン・ワークスペース切替・他を閉じる は、入力のあるペインを一覧したダイアログで確認する（既定とEscは「やめる」）。確認後にもう一度読み、入力・ページ・世代が変わっていれば実行しない。スリープ中・空・新しいタブのペインは読まずにそのまま実行する。ウィンドウを閉じる・アプリ終了は対象外
- 読み込みの順番待ち（`src/load-queue.js`）: アプリが始める読み込み（起動・ワークスペース・新しいペイン・再読み込み・一括更新・自動リロード・スリープからの復帰・URL変更/戻る/進む/ペイン内のgrok.comリンク・Bot表示の補正・スリープ中の新着確認）は全ウィンドウ共通の順番待ちを通り、同時に読み込むのは2枚まで（うち新着確認は1つまで）。順番は ユーザー自身の復帰・再読み込み・URL → 起動・一括更新・自動リロード → 新着確認、同じ順位ではフォーカス中のペインが先。同じペインへの重複した予約は1つにまとめる。待っているペインは「⏳ 読み込み待ち（n番目）」と「取消」を表示し（表示するページがまだ無いペインは空白の代わりに案内を出す。取消後はクリックで読み込む）、待っている間に入力が現れた・確認後に入力した場合は、ページを置き換える直前に入力欄を読み直して実行しない。ペインやウィンドウを閉じたときは読み込みを実際に止めてから（ビュー・確認用ウィンドウが消えてから）次を始める。新しいタブ・スリープ時の about:blank・承認Botポップアップは対象外
- 遷移・権限（`src/navigation-policy.js` / `src/permission-policy.js`）: URLは `new URL` で解釈し、スキームとホスト名（完全一致かサブドメイン。文字列の前方一致は使わない）で判定する。ユーザー名・パスワード付きURL、javascript: / file: / data: / chrome: などは開かない。ページ内リンク（target付き・window.open）・同じ枠での移動・メインフレームのリダイレクト・アプリ自身の読み込み（すべて `appLoad` 経由）・既定ブラウザ／外部アプリでの起動（すべて `openExt` 経由）に同じ方針を使う。grok.com はペイン内、ログイン系はポップアップ、その他のWebリンクは既定ブラウザ（従来どおり）。mailto / tel / sms / facetime は、そのページでのクリック・キー操作の直後か右クリックメニューからだけ。アプリUI（上部バー・overlay）は移動も新規ウィンドウもしない。アドレスバーの拒否URLは何もしない（ページはそのまま）、新しいペインなら新しいタブ。サイト権限（通知・クリップボード・マイク/カメラ・全画面・ストレージ）は従来の許可分だけを、grok.com 以外（chatgpt.com・gemini・claude.ai など）も含めて従来どおり許可する。ただし要求元の origin が正常なもの（https、http は 127.0.0.1 / localhost / [::1] のみ、ユーザー名なし）で、自分のページへの要求のときだけ: メインフレームはトップページと同一 origin、子フレームはトップページと同一 origin（例外として grok.com 内の grok.com 系フレーム。https・既定ポートの grok.com とそのサブドメインのみで、grok.com.evil.com などは対象外）、埋め込み元もトップページと同一 origin、ワーカーは origin が正常なら可（check / request 両方）。他 origin の子フレーム（広告・埋め込み・サインイン・challenges.cloudflare.com など）、null / 空 / 不正 origin、ユーザー名付き、http（loopback 以外）、file: / about:blank、未知の権限、マイク/カメラ以外のデバイスは拒否、裏の新着確認はストレージのみ。ダウンロードは見えているページからだけ、ページの名前はフォルダ部分・制御文字・向き変更文字・先頭末尾の点を除いて ~/Downloads に保存し、自動では開かない。拒否は診断に固定コード（`nav.block` / `perm.deny`）だけを残す
- ズーム（`src/zoom-policy.js`）: ペインは全体ズームに従うか「個別」（全体の変更を受けない）のどちらか。範囲30〜300%・10%刻み・リセット100%、保存形式（`zoom` / `zoomIndiv`）は従来どおり。Electron の `webContents.setZoomMode('isolated')` が使えるペインは、ビューごとに最初のページの前に isolated にしてから `setZoomFactor` で倍率を付ける（同じサイトの他ペインに伝わらない。再読み込み・移動・スリープの about:blank と復帰・↩ で開き直し・再起動でも保持）。API が無い・設定で例外・モードが isolated にならないときは、そのペインだけ従来方式（preload の `webFrame.setZoomFactor`、サイト共通の倍率は100%に保つ）。1つのページに両方は使わない。倍率は変更時と新しいページの表示時にだけ付け、フォーカス移動では触らない。承認Botポップアップと裏の新着確認は従来どおり既定モードの100%。どちらの方式になったかは診断の `zoom`（`NATIVE` / `NO_API` / `INIT_FAIL` / `MODE_FAIL` / `FORCED`、ページがモードを失って付け直した `MODE_RESET`、途中で従来方式に切り替えた `FALLBACK`）。開発時は `MPB_NO_NATIVE_ZOOM=1` で全ペインを従来方式にできる（未対応環境の確認用）
- 通知（`src/notification-policy.js`）: 光る・通知するかの判定（canAlert・`pane-state.js` の alert）は従来どおりで、その後の配送だけを決める。通知1件は「ペイン番号 + 世代 + 種別 + 報告キーの短いハッシュ」で識別し（本文・URL・名前は使わない）、配送済み・破棄済みのキーは最大200件・24時間だけメモリに持つ（再起動で空。起動直後の初回報告は従来どおり新着扱いしない）。最初の候補から4秒の間に来た候補は1通にまとめ、同じペインは1件と数える。通知オフ・ペインのミュート・静音時間（ローカル時刻、日跨ぎ可、既定オフ。`settings.quietHours`）の候補は捨てる。配送の時点で閉じた・前面で見ている・ミュートしたペインは出さない。1ペインの通知のクリックは、同じペインがまだ開いていて世代も同じときだけそのペインへ（眠っていれば起こす。既読にしない）、それ以外とまとめ通知はアプリを前面に出すだけ。診断は `notify` の固定コード（`SENT` / `MERGED` / `DUP` / `MUTED` / `QUIET` / `GONE` / `SEEN` / `OPEN` / `STALE` / `FRONT`）と件数だけ。開発時は `MPB_NOTIFY_DRYRUN=1` でOS通知を出さずに診断・デバッグログだけ残せる
- 閉じたペインの履歴（`src/closed-panes.js`）: 1枚ずつ閉じたペインごとに、`paneSpec` の範囲（URL・名前・色・ミュート・ズーム・個別ズーム・自動リロード・スリープ設定）と閉じた位置（行・列・行が消えたか・最大列数）だけをウィンドウごとのメモリに最大10件持つ（下書き・本文・スナップショット・token・ペインID は持たない。`panes.json` には書かない）。開き直すときは最新の項目を見るだけで、新しいID・世代の `addPane`（読み込みは順番待ち経由）が成功してから履歴から外すので、10枚・作成失敗・実行中の二重操作では消費しない。位置は `src/reopen-rules.js` の `placeReopened` で元の行へ戻す。キーボードのフォーカスは50ms後、その間に別ペインのクリック・入力・アドレスバー・パレットへの移動がなかったときだけ新しいペインへ移す。診断は `reopen` の固定コード（`OK` / `EMPTY` / `FULL` / `BUSY` / `FAIL`）と残り件数だけ
- 一斉送信（`src/broadcast-state.js`）: プレビューでは main が選ばれたペインをその場で読み（`liveInput`。スリープ中は読まない）、送信可 / 起床待ち / スキップ（入力あり・添付・アップロード・IME・確認できない・別の確認中・読み込み中・会話が未確定）を決める（何も送らない）。「このN件に送信」は画面上のプレビューから1回だけ batch を作り（二度押し・キーリピートは `DUP` で何もしない）、各送信先のペイン実体・世代・会話ID・キー入力の回数をプレビュー時点のまま固定する。送信先ごとに、直前の再確認（変わっていれば送らず「変更あり」でスキップ。別のペイン・会話に差し替えない）→ 入力欄が空のときだけ入力（既存の下書きは消さない・合成しない）→ 少し待って再確認 → 入力した内容のままなら送信ボタン（無ければ Enter）、と入力と送信開始を分ける。送信開始後は、同じ世代でユーザー発言数が増えた、または入力欄が空に戻った（その間キー入力なし）ときだけ「確認済み」。20秒以内に確認できない・ページの移動・クラッシュは「結果不明」で、自動では再送しない。処理中のペインは #11 の「一斉送信の処理中」になり、自動スリープ・自動リロード・置き換えの読み込みは止まり、手動の操作は確認を出す。スリープ中の送信先は既存の起床（読み込みの順番待ち）で起こし、その会話が新しい世代で確定してから同じ確認をする（起きない・別の会話になったらスキップ）。取消は入力前のものだけ（送信開始したものは止められない）。batch はメモリだけで `panes.json` に書かず、再起動で再開しない。**ネットワーク全体での exactly-once（重複も欠落もないこと）は保証しない**（「確認済み」は画面上の証拠で、相手への到達そのものではない）。本文は診断・ログに残さない（診断は `bcast` の固定コード `PREVIEW` / `START` / `DRYRUN` / `DUP` / `STALE` / `BUSY` / `SENT` / `OK` / `UNSURE` / `SKIP` / `CHANGED` / `NO_WAKE` / `CANCEL` / `DONE` と件数・ペイン番号だけ）。開発時は `MPB_BROADCAST_DRYRUN=1` で、プレビュー・起床・入力欄の確認はそのままに、ページへの入力・送信を一切せず結果を「結果不明（試験モード）」にできる
- スリープ状態の復元（`src/session-snapshot.js`）: 記録の作成（`make`）・読込時の検査と修復（`clean`。`src/state-schema.js` の migrate が使い、壊れた/新しい版は捨て、型・長さは直す。致命的にしない。ワークスペースには持たない）・起動時の判断（`plan`。設定ON・保存状態 ready・自動スリープONのペインだけ。7日超/時刻の不整合はマーカーなし）・再確認（`rechecked`）・表示文（`label`）を時刻を引数に取る純関数にまとめる。記録を付けるのはウィンドウ自身の保存だけで、ワークスペース・閉じたペインの履歴・複製は従来どおり `paneSpec` のみ。診断は `restore`（復元した数・マーカーを出さなかった数・使わなかった記録の数）
- スリープ中の新着確認の鮮度（`src/probe-policy.js`）: main がスリープ中のペインごとに最終試行・最終成功・連続失敗回数・次回予定・結果種別をメモリだけに持つ（`panes.json` に書かず、スリープに入るたびに新しくなる）。成功は「期待した会話の、使える安定した読み取りが結果になった」ときだけ（SAME / CHANGED / BASELINE）。不確か・タイムアウト・別サイト・ログイン画面・見つからない・エラーは失敗で、「新着なし」にせず、最終成功時刻も水色（未開封）も変えない。起床・中断・別のスリープの結果は失敗に数えない。間隔は通常5分、連続失敗で 5/10/20/40/60分（上限60分）、成功で5分に戻る（`MPB_CHECK_SEC` は基準間隔を変え、同じ倍率 1/2/4/8/12 で縮む）。時計が戻っても次回予定はその待ち時間より先にならない。15秒ごとの起動・同時1件・30秒の上限（ルーター経由の再表示3回と14秒以降の再読み込み1回を含む）・スリープ/ロック中と復帰後20秒・起動直後や一括更新後30秒・読み込み中の抑止・起床/閉じる/URL世代での取消は従来どおりで、期限を過ぎたペインが多くても1回に1件。確認窓の最後のURLが既知のログイン画面（`accounts.x.ai`、grok.com / x.ai / X / Google / Apple のサインイン・OAuth のパス）か、ページ自身の `AUTH_REQUIRED`（パスワード欄）のときだけ、共有セッションの確認を全ウィンドウで止め、スリープ画面に「ログインを確認」（そのペインを開く）「確認を再開」を出す（設定メニューにも「新着確認を再開」）。単に grok.com 以外へ移った・`DOM_UNKNOWN` では止めない。再開は手動の1回だけで、そのペインを次の確認対象にし、以後も1件ずつ。手動の「今すぐ確認」は設けていない（クリックで起こせば最新が見え、予定を迂回しない手動確認は速くならないため）。診断は `probe` に `BACKOFF`（n = 連続失敗回数）/ `AUTH_HOLD` / `RESUME` を追加（URL・名前は記録しない）

  - 普段はメモリに最新1000件だけ（終了で消える）。設定 >「診断ログをファイルにも保存」か `MPB_DEBUG` のときだけ `userData/diagnostics/diag-0〜2.jsonl`（フォルダ0700・ファイル0600、1ファイル2MiB・3世代・7日）に非同期でまとめて書く。書けない（満杯・権限）ときも記録とアプリは止まらず、失敗は1回だけ記録して間隔をあけて再試行。オフにしてもファイルは消さず、整理するのはこのフォルダの `diag-N.jsonl` だけ（`pane-debug.log` は別物で、URLなどを含むことがある）

## English
MultiPane Browser is an unofficial Electron-based macOS browser that tiles up to 10 web panes in one window, built for monitoring multiple Grok Bot chats side by side. Features: layout presets with auto-fit, draggable splitters, per-pane unread counts and glow, "waiting for input" highlight, native notifications and dock badge, favorites bar, tabs with context menu, compact mode, saved layouts, broadcast send, subscription usage readout, and a workaround for grok.com bot deep links. Run with `npm install && npm start`. Not affiliated with xAI or X Corp.
